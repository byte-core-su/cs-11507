# Firestore 用量控制與部署

本次處理大查詢與學生有效時間；原始作答、排行榜歷史、證書、出席與教師核定均保留。程式測試使用假資料，未讀取或更動正式 Firestore；網站更新不會自動部署資料庫規則與索引。

## 發布順序

1. 將本版 `firestore.rules` 發布至 Firebase Console 的 Firestore Rules。新增的 `quizAnalytics`（含整理進度及鎖定）只有指定教師可讀寫；歷史英雄榜快照只有教師可寫，登入學生可讀。私密答案、作答驗證與原始紀錄的權限不放寬。
2. 在 Firestore「索引 → 複合索引」建立以下三組；已有相同索引不必重建，不刪除其他既有索引。範圍均為 **集合（Collection）**，不是集合群組：

   | 集合 ID | 欄位順序 |
   | --- | --- |
   | `events` | `termId` 升冪、`createdAt` 升冪 |
   | `bests` | `score` 降冪、`studentId` 升冪 |
   | `scores` | `studentId` 升冪、`score` 降冪 |

   定義也保存在 `firestore.indexes.json`。等狀態變成「已啟用」再繼續；需要索引時不會自動改讀整個集合。若採 Firebase CLI，請將規則與索引路徑併入既有部署設定，勿以此檔覆蓋其他專案設定。
3. 發布新版網站並重新整理教師端，進入所需學期「題目分析」。選「全年級 → 整理／接續全年級」即可依序整理缺少完整快照的班級；已經整理完的班級會略過。每按一次跨班合計最多掃描 5,000 筆作答，進度按學生、每頁最多 200 筆分段保存。顯示未完成時再按同一個按鈕；離開或關閉分頁後也能從已保存的進度接續。若正好到達上限，可能需要再按一次來確認該班已無待整理資料。所有班級完成後自動顯示全年級統計。
4. 各班都已整理、有新作答時，選「全年級 → 增量更新／接續全年級」；只查各學生進度點後、該輪開始時已送出的作答。每次跨班共用 5,000 筆上限，未完成時再按同一按鈕，已完成本輪更新的班級不重查。更新開始後才送出的作答留到下一輪。這期間可查單班舊有或已完成的快照，但必須先接續完成本輪，才能重讀全年級統計或執行其他題目整理；這是為了避免新舊班級統計混用。平時只查看上次結果可按「載入／重讀彙總」，不會掃描新作答；只需更新單班可按「整理／增量更新」。若已部署這份文件所列規則和索引，新增全年級按鈕不需要再部署。
5. 在「英雄榜歷史快照」選簡單、普通、困難，各按「建立／接續快照」直到完成；上下學期分開準備（共六份）。只有明確按鈕才掃描舊 `scores`，每次最多 5,000 筆。歷史集合已禁止新寫入，完整快照完成後不再重掃；現行 `bests` 則繼續保存新成績。快照未完成時學生會看到準備中提示，而非錯誤的部分排行。
6. 學生重新開啟新版頁面後開始套用有效時間；舊頁面仍可能執行舊程式，應請學生與教師關閉舊分頁。使用 HTTPS 及支援 Web Locks 的瀏覽器；無此功能時僅暫停計時，不阻擋課程。此更新不需 Apps Script 重新部署或學生重做任務。

## 讀寫估算

以下是文件讀寫估算，不含其他課程頁、索引項目、規則額外讀取、網路重連及失敗前已送出的請求。不可當成 Firebase 帳單保證。

| 動作 | 新版估算 |
| --- | --- |
| 題目分析開著不動一小時 | 0 次背景讀取、0 次整理寫入；必須按按鈕 |
| 重讀單班彙總 | `1 + ceil(該班不重複題數 / 100)` 份文件；例如 300 題約 4 次，而非重新讀取數萬筆作答 |
| 重讀全年級 | 各班上述讀取量相加，另檢查兩次增量更新狀態；11 班各 300 題約 46 次 |
| 初次／增量整理單班 | 名冊及學生查詢 + 各學生已存彙總 + 新作答（最多 5,000 筆）+ 查詢空頁／鎖定等。只有限制原始作答掃描數，**並非整次操作總讀取不超過 5,000**。整理會保存學生分頁、進度點與完整班級快照，亦有寫入成本 |
| 整理／接續全年級 | 先查各班快照是否完成，只對未完成的班級執行上述整理；每次跨班共用 5,000 筆原始作答掃描額度。全部完成後另讀取班級彙總以顯示統計 |
| 增量更新／接續全年級 | 只對尚未完成本輪的班級查名冊、學生彙總與進度之後的作答，跨班共用 5,000 筆額度；即使沒有新作答，仍有檢查與接續進度成本。已有來源進度且資料未變的班級不重寫快照 |
| 英雄榜開一次 | 1 份歷史快照 + 最多 20 份現行最佳；重複開啟同難度在同頁 60 秒內共用快取。開著不動不自動更新 |
| 存個人最佳時查舊成績 | 排序並 `limit(1)`，最多一份舊成績；另有既有交易讀寫 |
| 學生持續在單一前景分頁操作一小時 | 初始訊號約 1 次 + 每 2 分鐘約 30 次，離開最多再 1 次；不因頻繁聚焦增加一批寫入。同 UID 多分頁共用互斥鎖，只有計時者會寫 |
| 學生頁面前景閒置一小時 | 初始 + 第 2、4 分鐘 + 第 5 分鐘收尾，約 4 次；最多累計 5 分鐘，之後停止該分頁計時與登入識別監聽 |
| 學生頁面背景一小時 | 停用收尾之後 0 次定時寫入；回來先驗證登入識別，再繼續，不補計隱藏期間 |

教師即時班級監聽仍會讀取該班有變動的學生文件，故學生心跳減少也可間接減少教師端讀取。本版沒有把所有學生頁的所有 Firestore 監聽移除，也沒有更動答案驗證或減少真實作答紀錄。

## 準確性與限制

- 整理只處理既有系統的有效逐題格式：不可改寫的 `quizAttempts/{uid}/events`，具有 `termId` 與伺服器 `createdAt`。索引不含缺少排序欄位的文件；本系統現行規則一向要求 `createdAt == request.time`。人工另行匯入、缺欄位或回填過去時間的紀錄，須另行規劃受控重建，不能假設本次增量查詢會自動納入。沒有逐題紀錄的證書不會捏造作答。
- 每位學生的摘要保存首次作答時間、首次正誤、總次數及選項數；增量只接續不可變更的原始事件。全年級用實際次數合併，不平均各班百分比。轉班造成班級快照重複 UID 時拒絕顯示，請重新整理轉出與轉入班級。
- 班級與個人快照分頁使用同批次版本標記；若更新途中讀到不一致版本，顯示稍後手動重讀，不混合部分資料。教師整理工作使用同學期限時鎖，同時只能一個整理工作；逾時鎖可在兩分鐘後由下一次手動操作取得，沒有背景續跑。
- 新版計時採單調時鐘，每 10 秒在本機取樣；間隔超過 30 秒視為休眠／計時器暫停，不補算整段，可能少算一小段但不會膨脹為數小時。只有前景、有焦點、在線且伺服器確認目前登入識別時才計時。閱讀時無操作最長計 5 分鐘，外部應用不列入。
- 心跳每 2 分鐘累加，隱藏／失焦／閒置時嘗試收尾，不保證瀏覽器關閉最後請求成功。短暫未滿間隔的餘額只依專案、學期、UID 暫存秒數，不存學生作品或憑證；清除網站資料或錯誤會造成少算。模糊失敗的增量不自動重送，避免可能已成功的寫入被再次加算。
- `totalActiveSeconds` 原值保留，新增 `activeV2Seconds`、`measurementVersion`、`measuredSince`、`legacyActiveSeconds`。教師表格分別顯示累計及新版有效時間；平均累計仍含舊值，不能用新版規則回溯更正舊制時間。不會清空學生進度或更動評分。
