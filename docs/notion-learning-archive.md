# Notion 學習作品整理

教師端的「Notion 整理」頁面以系統名冊為唯一學生來源，將每位學生的「資訊生活、演算流程、運算思維、程式設計」各 8 項，共 32 項整理為學習展示卡。補交、重新檢核或更換 Classroom 作業時，仍以學期、班級、學號與任務鍵更新同一張卡。

學號結尾 `00`（例如 `1510100`、`1520100`）為測試帳號，不計入 Notion 人數或單元可同步人數，不匯出至名冊／作品索引 CSV，也不建立或更新 Notion 名冊、作品卡與證書。排除依學號判斷，不依可修改的座號欄位判斷。教師端仍可管理、檢核及查看測試帳號的個人進度，並標示「測試」；繳交、出席、平均進度／時間、全班平均成長曲線、任務排名與各班／全年級題目分析不計入測試帳號。原始 Firebase 資料保留。

已同步的測試資料需在 Notion 手動清理：在「學習作品」新增暫時的表格檢視，不套用類別或學期條件，篩選「學號等於 1510100」，核對後將該學號的作品列移到垃圾桶；再到「學生名冊」篩選同一學號，將對應名冊頁移到垃圾桶。其他誤同步的測試學號分別處理。只移除資料列／作品頁，不刪資料庫、欄位或連接。新版排除規則不會自動刪除既有頁面；前端推送與 Apps Script 更新部署後，再次同步不會建立或更新測試帳號頁面。

## 教師端操作

1. 在「Notion 整理」直接選擇班級，不必回到「作業檢核」切換班級。兩頁的班級切換互相獨立，Notion 的名冊匯出與作品同步都以此處選定的班級為準；分類與單元沿用作業檢核，沒有另外一份任務對照表。
2. 資訊生活與演算流程共 16 項直接讀取本學期通關紀錄，不需對應 Classroom，既有通關學生不必重新作答。
3. 運算思維與程式設計共 16 項直接讀取「作業檢核」保存的本學期、單元與採認附件。只需在作業檢核中選定單元、作業與採認檔案並核可一次；Notion 不必重新讀取 Classroom、選擇作業或儲存對照。來源表會顯示每項可同步人數，缺少完整採認資訊者會提示重新檢核。
4. 下載兩種 CSV：
   - **學生名冊 CSV**：每位學生一列，可匯入 Notion 的學生資料庫。
   - **作品索引 CSV**：每位學生 × 32 個任務一列，包含類別、名稱、資料來源、通關／上傳時間、核定狀態，以及有紀錄時的得分、正確率與作答秒數。
5. 選擇一項任務按「同步指定任務到 Notion」，或按「同步本班全部 32 項」。尚未完成的項目可先建立空白卡，之後核可再同步即可更新。
6. 系統每批處理 4 位學生，顯示目前任務與學生進度。請保持頁面開啟；可按「完成本批後停止」，已完成的批次保留。個別學生寫入或確認失敗時，會繼續處理同批及後面的學生，並列出學號、姓名、任務與原因；該項不計入成功證書件數。中斷或失敗後可再次同步，會更新原卡，不需刪除重建。整批連線、權限、資料格式或設定錯誤則停止並提示，已完成的內容保留。

「可同步 28 / 28 人」代表平台找到 28 位學生的有效來源紀錄，不代表 Notion 已收到 28 張圖片。成功證書件數依 Notion 寫入後讀回的封面、作品附件、正文圖片、通關狀態與證書索引確認；若只有空白卡、圖片未完整掛入，會顯示失敗，不以已送出的圖片數代替成功數。

選取欄位沒有填寫說明也能同步：更新選項時僅帶入原有非空白說明，空字串、`null` 或未設定的說明會省略，不會送出 Notion 不接受的空 `description`。若舊版出現 `description.length should be ≥ 1`，請更新最新版 Apps Script 並新增部署版本後重試，不需手動替欄位補說明或刪除資料。

同步前會自動補上本批缺少的選取選項：「學生名冊」的班級，以及「學習作品」的班級、學期、類別與教師狀態。原選項、顏色、選項說明及欄位說明保留；完成設定更新並讀回確認後，才開始篩選與寫入學生作品。這避免原本只有 701 選項時，切換 703 班同步就因班級篩選失敗而中止。若仍使用舊版指令碼，可暫時在兩個資料庫的「班級」選項各新增 `703` 後重試，不要將 `701` 改名；永久修正須更新最新版 Apps Script 並新增部署版本。設定更新權限不足時會停止並提示，不改以錯誤班級匯入。[Notion 選項更新規則](https://developers.notion.com/reference/update-data-source-properties) 為處理依據。

## 集章證書與作品來源

| 類別 | 認定依據 | Notion 展示內容 |
| --- | --- | --- |
| 資訊生活 | 本學期證書紀錄與取得時間 | 自動產生的 PNG；保留單元、學生、時間及有紀錄的測驗資訊 |
| 演算流程 | 上學期的排序完成時間；下學期的 Mermaid code 產生紀錄 | 自動產生的 PNG；有通關得分時一併顯示 |
| 運算思維 | 本學期、該單元的作業檢核核可紀錄與採認附件 | 採認 PNG 原圖或 Google 繪圖匯出的 PNG；附件、正文、封面及原始連結 |
| 程式設計 | 本學期、該單元的作業檢核核可紀錄與採認附件 | 採認的 MP4 連結 |

學生端上下學期的程式設計頁面都有 8 格「流程圖集章牆」，完成後可查看／下載證書 PNG；資訊生活原有證書也可下載 PNG。下學期僅完成教練討論或達到 85 分，尚未產生 Mermaid code 時，不核發流程圖集章。重新闖關未達標不會用低分覆寫已保存的成功通關得分；舊紀錄若缺少成功得分，證書仍可依完成時間核發，但不虛填分數。

教師同步時會依通關紀錄與現有名冊即時產生 PNG，經 Apps Script 直接上傳到 Notion 的檔案儲存空間，設定為作品附件、正文圖片與頁面封面。不另建公開的 Firebase／Drive 圖片網址，金鑰不會傳到學生端；不需額外 Google Drive 寫入權限。同一圖片未變更時，先確認舊上傳仍有效才沿用；檔案不存在、失效或尚未完成上傳時改為重新上傳，權限或連線錯誤則明確列為失敗。每次同步均刷新正文圖片引用及封面、附件，補齊缺圖；姓名或通關紀錄變更後再同步會更新圖片。來源紀錄未完成者只建立空白卡，不會產生虛假的證書。

空白卡後來有通關紀錄時，會在補圖成功後移除自動管理區塊中的「尚無本學期通關紀錄；完成後同步即可展示證書。」舊提示；不重複建立作品卡或證書標題。若通關紀錄移除，再同步會恢復尚未完成提示。只整理系統產生的提示及證書圖片，教師自行增加的筆記與圖片保留；移除的系統區塊使用 Notion 垃圾桶機制，可復原。這項修正避免先建立空白卡後，舊提示殘留而與教師端通關狀態矛盾。

運算思維與程式設計是否完成仍以教師端核定紀錄為準；學生自行上傳附件只會成為待檢核的證據，不會直接變成通關紀錄，也不會將附件匯入 Notion。只有該學生、本學期、該單元的教師核可紀錄中明確採認的那一件附件才匯入；多件附件不會自動選第一件。尚未核可、需要補件或缺少完整採認資訊者只保留名冊與空白任務卡；舊版核可紀錄若未保存採認附件或課程／作業識別，需回「作業檢核」重新選定並核可。資訊生活與演算流程不需教師逐件核可，依系統通關紀錄產生證書。

運算思維的採認附件現在會實際上傳圖片，不只是網址：PNG 透過教師授權讀取原圖，Google 繪圖透過 Drive 匯出 PNG，再上傳至 Notion，掛入作品附件、正文與封面；原始網址仍保留在作品連結及正文，方便回查。圖片上限為 10 MB，超過上限、非 PNG／Google 繪圖、禁止下載、教師無權讀取或內容不是有效 PNG 時，會列出該學生與原因，不假裝同步成功。每次重新讀取原檔確認內容；相同圖片且舊上傳有效時沿用，原檔修改或重新採認後刷新，過期圖片自動重新上傳。「作品圖片索引」供系統比對，不需手動填寫。舊連結卡再同步即可補圖，不重建卡片。Google 匯出及讀取方式見 [Drive 下載與匯出](https://developers.google.com/workspace/drive/api/guides/manage-downloads)。

運算思維圖片上傳後為 Notion 儲存的副本，依 Notion 頁面的分享權限顯示，不再沿用原始 Drive 的檔案存取限制；對外分享前請確認分享對象。此功能不會把 Drive 原檔設為公開，也不會修改學生檔案。程式設計維持影片連結，不下載或轉換 MP4，影片仍依原 Drive／Classroom 權限存取。

切換班級後，來源表直接顯示該班現有紀錄，不需額外載入作業清單。同步期間會暫停 Notion 班級切換，避免操作中途混用班級資料。教師後續改為補件或重新採認後，再按同步便會更新原卡。每位學生可保留不同補交作業的實際採認來源，不以另一份共同對照覆寫。新檢核紀錄會保存作業名稱；舊紀錄有採認附件與課程／作業識別但沒有名稱時，顯示作業 ID，不需為補名稱而重新核可。

## 建議 Notion 結構

不要建立大量深層資料夾。建立兩個資料庫後，用關聯、篩選與群組呈現「類別 → 班級 → 學生 → 作品」：

### 1. 學生名冊

| 欄位 | 類型 |
| --- | --- |
| 姓名 | 標題 |
| 學號 | 文字 |
| 班級 | 選項 |
| 座號 | 數字 |
| 同步鍵 | 文字 |

匯入「學生名冊 CSV」時，將 CSV 的「姓名」指定為標題欄位。

### 2. 學習作品

| 欄位 | 類型 |
| --- | --- |
| 名稱 | 標題 |
| 學生 | 關聯至「學生名冊」 |
| 學期 | 選項 |
| 班級 | 選項 |
| 座號 | 數字 |
| 學號 | 文字 |
| 類別 | 選項 |
| 任務鍵 | 文字 |
| 任務名稱 | 文字 |
| Classroom 作業 | 文字 |
| 教師狀態 | 選項 |
| 作品上傳時間 | 日期 |
| 教師核定時間 | 日期 |
| 作品連結 | 網址 |
| 作品附件 | 檔案與媒體 |
| 同步鍵 | 文字 |

首次同步時，程式會在「學習作品」自動新增下列欄位，不需手動建立；若已存在，須符合類型：

| 欄位 | 類型 | 說明 |
| --- | --- | --- |
| 證書索引 | 文字 | 系統用來沿用未變更的證書，展示時可隱藏 |
| 作品圖片索引 | 文字 | 系統比對運算思維 PNG 內容及有效上傳，展示時可隱藏 |
| 通關得分 | 數字 | 有紀錄時保存，不代表正式評量分數 |
| 正確率 | 數字 | 有紀錄時保存，範圍為 0–100 |
| 作答秒數 | 數字 | 有紀錄時保存 |

「同步鍵」、「證書索引」與「作品圖片索引」由系統使用，請保留但不必在作品牆卡片顯示。作品附件可以是 Notion 直接儲存的證書／採認 PNG，或程式設計的 HTTPS 外部連結；外部連結仍受 Google Drive／Classroom 原始權限控制。系統證書的「作品連結」保持空白；運算思維保留原始 Classroom／Drive 連結，不使用會到期的 Notion 下載網址當作永久連結。

CSV 匯入只包含文字紀錄，不會上傳 PNG；圖片與作品附件須使用教師端同步按鈕。手動匯入 CSV 後，將「學生」欄位逐步關聯到學生名冊；直接同步則由程式建立關聯。資料庫可建立四個檢視：

- **資訊生活**：篩選「類別＝資訊生活」，以圖庫檢視、卡片預覽選「頁面封面」，展示通關證書。
- **演算流程**：篩選「類別＝演算流程」，同樣以頁面封面展示流程圖證書。
- **運算思維**：篩選「類別＝運算思維」，依班級、學生群組；使用圖庫檢視，於檢視設定的「版面配置 → 卡片預覽」選擇「頁面封面」，即可直接展示教師採認圖片。原連結仍可在作品頁查閱。
- **程式設計**：篩選「類別＝程式設計」，依班級、學生群組；每一頁可放該生的成果影片連結。

作品牆可再依班級篩選或學生分組。證書圖片預覽不會改變頁面分享權限；對外分享含姓名、學號的作品牆前，應確認分享對象與校內個資規範。圖庫檢視只調整呈現，不等於限制其他資料的存取權限。

## 啟用前置設定

Notion 整理直接讀取既有教師核定紀錄；分類整合不新增 Firestore 欄位權限或要求重設資料庫。舊 `teacherSettings/notionSync` 對照資料保留，但新版不再讀寫，無須手動刪除。

目前 CSV 匯入可立即使用。若要做成按下教師端按鈕後直接建立／更新 Notion 作品頁，請依下列方式設定。

### Apps Script 的安全連線設定

1. 以目標 Notion 工作區的擁有者身分，在 Notion `Settings → Connections` 開啟 Developer Mode，建立一個內部 Connection。它需要 **Read content、Insert content、Update content** 三項內容權限。
2. 在「學生名冊」與「學習作品」資料庫右上 `••• → Connections`，各自加入這個 Connection；兩個資料庫都必須加入。
3. 取得兩個資料庫的 **Data source ID**：資料庫設定 `Manage data sources` 中，對資料來源按 `••• → Copy data source ID`。請使用 Data source ID，不是網頁網址或一般 database ID。
4. 開啟本專案的 Apps Script，選擇 `Project Settings → Script properties`，新增下列三項。值只能直接貼在這裡，**不可放進本網站、Firebase、GitHub 或聊天訊息**：

| 指令碼屬性 | 值 |
| --- | --- |
| `NOTION_API_TOKEN` | 此 Connection 的 internal token |
| `NOTION_STUDENTS_DATA_SOURCE_ID` | 「學生名冊」Data source ID |
| `NOTION_WORKS_DATA_SOURCE_ID` | 「學習作品」Data source ID |

5. 在 Apps Script 內貼上最新版 `shared/google-classroom.gs`。專案設定中開啟「在編輯器中顯示 appsscript.json 資訊清單檔案」，到 `appsscript.json` 將 `oauthScopes` 更新為 `shared/google-classroom-appsscript.json` 的清單，保留該專案其他設定。新清單包含 `https://www.googleapis.com/auth/drive.readonly`，讓教師可讀取採認圖片內容，沒有 Drive 寫入權限。儲存後以教師帳號在編輯器執行 `authorizeClassroom`，允許新增的唯讀權限。再到「部署 → 管理部署作業 → 編輯 → 版本選擇新增版本 → 部署」，保留原 Web App 網址、執行身分及校內存取設定。若學校管理政策阻擋新權限，需請管理員核准；不要改成公開檔案來繞過。
6. 回到教師端「Notion 整理」。當畫面顯示「Notion 連線已完成」後，選班級即可同步指定任務或全部 32 項，不需再設定 Classroom 作業對照。若畫面提示需更新後端，請確認已將最新版程式部署為新的 Web App 版本，再重新開啟教師頁面。

每次同步會分批處理該班所有學生：先建立或更新學生名冊，再更新指定任務或全部 32 項展示卡。Classroom 的 PNG 與 Google 繪圖僅寫入運算思維任務，MP4 僅寫入程式設計任務，而且必須是教師核可的採認附件。資訊生活與演算流程則直接上傳由系統通關紀錄產生的 PNG，未完成者不產生圖片。

更新同一作品卡時，附件欄位及系統產生的附件區塊會一併刷新。Classroom 作品改為需要補件或重新採認後，再同步即可移除舊的自動附件連結；運算思維取消核可／改為補件後，會同時清空系統封面、附件與圖片索引，並將系統圖片區塊移到垃圾桶。系統證書來源紀錄移除後，再同步也會清空封面與附件欄位，並將系統證書圖片區塊移到垃圾桶，仍可復原，作品卡不刪除。教師自行增加的圖片與自動管理區塊以外的筆記不會清除。未選入本次同步的任務不受影響。

完整 32 項、證書上傳、附件核可限制及運算思維圖片上傳均包含 Apps Script 後端更新，須更新 `shared/google-classroom.gs` 與資訊清單的 `oauthScopes`、完成新增 Drive 檔案內容唯讀授權並新增部署版本。既有 Notion 指令碼屬性不需更改。

圖片同步與結果確認使用 `learning-archive-v5`，包含先前證書補圖修正。網站推送不會自動更新 Apps Script；請依上述步驟更新資訊清單、完成新權限授權並新增部署版本，維持原本 Web App 網址。重新開啟教師端，確認不再顯示更新後端提示，再同步原班級及指定任務。舊版直接同步會被阻擋，CSV 匯出仍可使用。無須手動建立新欄位、刪除作品卡或讓學生重做測驗。

若重複同步曾出現 `body.image.type should be not present`（HTTP 400），原因是既有圖片區塊更新不接受新增圖片所使用的 `image.type` 欄位。最新指令碼已區分新增與更新格式；此格式錯誤不需清除資料，但升級 v5 的運算思維圖片功能仍須完成上述 Drive 檔案內容唯讀授權及新增部署版本。[Notion 區塊更新格式](https://developers.notion.com/reference/update-a-block) 與 [官方 SDK 欄位定義](https://github.com/makenotion/notion-sdk-js/blob/main/src/api-endpoints/common.ts) 為修正依據。

Notion 的連線金鑰只由 Apps Script 在伺服端讀取。資料列、正文圖片與圖片上傳分別使用 Notion 的資料來源、頁面／區塊及檔案上傳 API。[Notion connection capabilities](https://developers.notion.com/reference/capabilities)、[Query a data source](https://developers.notion.com/reference/query-a-data-source)、[Uploading small files](https://developers.notion.com/guides/data-apis/uploading-small-files)、[Retrieve a file upload](https://developers.notion.com/reference/retrieve-file-upload) 與 [Update a data source](https://developers.notion.com/reference/update-a-data-source) 為相關操作依據。
