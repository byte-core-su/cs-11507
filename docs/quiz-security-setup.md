# 題庫安全金鑰與作答統計初始化

本系統將選擇題正解與流程排序解答保留在 Firestore 的 `quizAnswerKeys`，學生網頁只保留題幹、選項與可操作的積木。學生送出後，Firestore Security Rules 才依答案金鑰寫入不可修改的作答紀錄。

## 一次性設定

1. 在 Firebase Console 的 Firestore Rules，部署本專案的 `firestore.rules`。
2. 使用教師帳號登入系統後，開啟 `shared/quiz-key-import.html`。
3. 選取本機 `private/quiz-answer-keys.json` 並匯入。
4. 成功後保留離線備份或刪除該金鑰檔；不可推送至 GitHub 或提供給學生。

## 作答統計資料

每次送出會建立 `quizAttempts/{uid}/events/{attemptId}`，包含學期、題號、題幹、作答選項或排序、正確與否、作答秒數及時間。教師端的「題目作答分析」可選各班或「全年級」（701–711 班），讀取本學期紀錄，以題號彙整作答人數、首次答對率、總答對率、選項分布及平均作答秒數，並顯示作答來源。全年級合併各班相同題號，首次答對率依每位學生該題的第一次作答計算，總答對率依所有實際作答計算，不取各班百分比平均；沒有登入建立學生資料者不計入作答人數。排序活動不列入 A／B／C 選項次數。

教師端直接讀取所選範圍內學生各自的 `quizAttempts/{uid}/events`，不使用跨集合查詢；此調整不需新增跨集合索引、放寬 Firestore Rules 或更動答案驗證。切換各班／全年級與登出會停止原有讀取，學生後續作答會即時更新統計。全年級需讀取較多學生，請等候完整載入。畫面會區分載入中、資料讀取失敗與尚無紀錄；失敗時可按「重新讀取作答紀錄」重試，資料未完整載入時不顯示可能誤導的部分統計。

既有逐題紀錄會直接納入，不需要學生重新通關。早期只有證書而沒有逐題紀錄的資料，不能由證書推算選項分布、作答秒數或首次答對率，也不會產生虛構紀錄。

此機制適用於教學診斷；學生仍可重複嘗試選項，因此不可直接作為正式評量成績。
